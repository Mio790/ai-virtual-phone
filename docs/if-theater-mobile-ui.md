# PR #2：IF 剧场移动端 UI 修正

首次主题修正基于 144b101；本次聊天空间修正基于 7fdde165，继续 feat/if-theater / Draft PR #2，不重建 A/B/C，不合并、不正式部署。

## 本轮重点：聊天阅读空间

上轮仍将 API 下拉、多行文本框、三颗按钮和说明常驻底部，把分支、记忆及 Prompt 放在剧情滚动区，未解决实际空间分配问题。本轮改为：

- 简短标题栏显示当前存档/分支短 ID；消息区独立滚动，打开/重进存档默认定位最新。上翻阅读后不强行跟随流式输出；切换分支重新定位最新。
- 底部只保留输入框与一颗发送/停止按钮。输入框单行 44px 起，按内容增高，最高 112px 或可视高度的 22%（至少 44px）；超长草稿在框内滚动。停止仅在有活动生成控制器时显示。
- 右上角设置内保留 API 选择、分支切换/另存、记忆、角色快照刷新及中断回复恢复入口。未选 API 时输入框提示前往设置，不自动请求。
- 待发送/最近 Prompt 在独立只读弹层查看；生成只更新快照，不自动打开。Prompt 不进入剧情流，不增加 API 请求。
- 桌面两颗全局快捷/Prompt 浮钮仅在 IF 阅读中暂时隐藏，返回大厅/退出恢复；组件保持挂载，不写全局开关，不改变其他 App 设置。桌宠/音乐功能未修改。
- visualViewport 变化仅收缩 IF 根节点，并重新计算输入高度/在跟随状态下对齐末条消息；不改 body，不触碰数据结构。键盘出现时减去多余底部安全区留白。真实 Safari 键盘、焦点平移及 PWA 行为仍需实机验收。
- 按 React 检查清单复核：UI 状态与领域数据分离，effect 使用稳定的读取状态/回调依赖，弹层含焦点恢复与键盘约束；未新增请求 effect。

## 问题与修改

旧页面使用无显式视觉样式的原生按钮，并把输入文字设为固定 #111、页面固定为深色背景。说明文字、按钮和表单混在同一个滚动块内，确实不适合 iPhone 操作。

- 使用现有小手机核心主题变量：页面、标题栏、面板、输入底色、强调文字及边框。移除固定深色页面和固定黑色输入文字；新增 CSS Module，仅作用于 IF 剧场。
- 大厅采用剧本卡片和可点击的存档卡片；“新建剧本”“新存档”是实心主按钮，编辑/复制是有边界的次按钮，删除有警示边框。说明、计数和只读标签与按钮区分。
- 编辑页将标题、完整世界观、时刻、开场白、主控和规则拆为独立有边界的编辑卡片，附提示、占位符、字符数及关联标签。角色采用整块可勾选卡片；时代身份单独编辑，原卡仍只读。
- 所有按钮基线触控区至少 44×44px；角色卡至少 52px 高；禁用态变淡并用虚线边框，键盘焦点有明确轮廓。输入框字体至少 16px，减少 Safari 聚焦放大；占位符及输入边界不再依赖浏览器默认颜色。
- 标题栏、独立滚动内容和底部表单/聊天操作栏分层；复用现有安全区变量。只在 IF 根节点响应 visualViewport 变化，不改变 body、桌面或其他 App 的高度。键盘收起恢复可视高度；尺寸较小时紧凑排版。
- 聊天页明确显示当前存档短 ID；分支下拉和“另存当前分支”移入设置；回复版本使用左右按钮、“当前回复版本”和版本计数，不与存档混淆。
- Send/Stop 按状态替换；Prompt 移入设置中的独立弹层。长按/操作按钮打开中文操作弹层，含 Re-roll、Edit、Backtrack、Delete 的清楚说明。弹层含 modal 语义、键盘焦点、Escape 和 Tab 约束。
- 流式内容只在接近底部时跟随，向上阅读不会被持续拉回末尾。历史正文保持完整，仅大厅世界观摘要作视觉行数限制，不截断保存数据或 Prompt。

## 不变的边界

lib/if-theater、stream、turn、storage 以及备份/现代记忆等领域模块没有修改。数据结构、角色 characterId/快照、专属记忆、单次请求、Stop 持久化、Re-roll、Swipes 和分支语义沿用原实现。没有新增自动请求、自动总结、NPC 或写回原角色卡。
